# Новини Windows-лаунчера

Підготовлено й перевірено локально 9 листопада 2026. Власник погодив commit і push. Готовність production та підключення Windows-плеєра перевіряються окремо після деплою.

- `GET /api/launcher?action=news` і `/api/site?action=news` — стара загальна стрічка, без новин з новими параметрами показу. Версія схеми — **1**, без V2.
- `GET /api/launcher?action=news&audience=launcher` — Windows-лаунчер: старі новини плюс ті, що позначені «Показувати в лаунчері». Стрічки мають до 12 опублікованих записів, найновіші першими.
- «Показувати в стрічці на головній» додає матеріал до домашньої стрічки (bootstrap), з MP4-плеєром у картці. Обидві галочки — обидва місця, жодної — матеріал приховано. Окремі сторінки нових записів `/news/:slug` повертають 404. Старі записи без нових параметрів зберігають колишні сторінки й канали показу.
- Це фільтрація аудиторій, не автентифікація Windows. Лаунчерна стрічка та медіа опублікованих записів доступні за своїми URL без логіна. Не використовуйте цю галочку для конфіденційних матеріалів.

Приклад відповіді Windows (демонстраційні URL/ID):

```json
{
  "schemaVersion": 1,
  "news": [
    {
      "id": 42, "title": "Відеоновини", "excerpt": "Огляд оновлення",
      "image": "",
      "video": "https://united-rp.com.ua/media/news/5ee08fa6-671a-4879-a777-b42c20227ab4.mp4",
      "launcherOnly": true,
      "hasPage": false,
      "url": "https://united-rp.com.ua/news/update-video",
      "publishedAt": "2026-11-09T14:00:00.000Z"
    },
    {
      "id": 41, "title": "Новина з фото", "excerpt": "Опис",
      "image": "https://united-rp.com.ua/assets/world.jpg",
      "url": "https://united-rp.com.ua/news/update-photo",
      "publishedAt": "2026-11-09T13:00:00.000Z"
    }
  ]
}
```

У Windows спочатку перевірити непорожній HTTPS `video`; якщо він є, передати його MP4-плеєру. Інакше показати `image`. `video`, `launcherOnly` та `hasPage` необов’язкові. Якщо `hasPage === false`, не показувати перехід до `url`: поля старого контракту збережено, але окремої публічної сторінки немає. `launcherOnly:true` означає, що позначено лише лаунчер. Показувати заголовок, опис та медіа у лаунчері.

Редактор завантажує MP4 прямо через сайт (максимум 20 МіБ, частинами по 1 МіБ до поточного API адмінки); новий бакет або секрет не потрібні. Зберігається в наявній MySQL. Міграція 013 створює три таблиці та не змінює старі новини. Сервер перевіряє контейнер, цілісність частин і взаємовиключення фото/відео. Це не перекодування: для Windows бажано H.264 + AAC. Посилання на YouTube не є MP4 і не приймається.

Для опублікованого прив’язаного відео HTTPS URL незмінний, без тимчасового підпису. `GET` → 200 `video/mp4`; `Range: bytes=0-1023` → 206 + `Content-Range` для відповідного розміру; `HEAD` → заголовки без тіла; некоректний діапазон → 416. Чернетки, зняті й від’єднані відео не роздаються анонімно (якщо той самий ролик ще не використаний у іншій опублікованій новині). Від’єднання не видаляє файл з БД; незавершені завантаження старше доби прибирає штатна команда `forum:cleanup`.

Локальна перевірка: `npm run test:news-video:integration` із ізольованою MariaDB; реальний loopback HTTP, повний потік понад 5 МіБ, Range через межу двох частин, HEAD/416, стара новина з фото, перемикання фото → відео → фото, серверні відмови при змішаних даних, фільтр аудиторії. Тестові дані перевіряють MP4-контейнер і транспорт, не декодування Windows. Після деплою перевірити справжній кліп на робочому домені, зокрема потік понад 4,5 МБ та перемотку у Windows; локальний тест не підтверджує поведінку проксі Vercel.

Довідка: [ліміти тіла і потокові відповіді Vercel](https://vercel.com/kb/guide/how-to-bypass-vercel-body-size-limit-serverless-functions).
