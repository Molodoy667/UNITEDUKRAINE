# Android v17: список серверів /online.json

Дата: 21 жовтня 2026, Europe/Bucharest. Проєкт: UNITEDUKRAINE.

## Підтверджена причина

Android-клієнт запитує `https://united-rp.com.ua/online.json`, розбирає JObject і читає `crmp_new`. За діагностикою клієнтського чату цей шлях підтверджено в IL2CPP; APK тут не змінювався. Локальний артефакт діагностики: `server-list-diagnosis.json` у каталозі аналізу Android-проєкту.

В актуальному до виправлення `vercel.json` немає `/online.json`. Останній rewrite `/(.*)` повертає `/index.html`. Незалежна публічна перевірка підтвердила HTTP 200, `Content-Type: text/html; charset=utf-8`, `Content-Disposition: inline; filename="index.html"`. Це відповідає помилці клієнта `Unexpected character ... <`.

Одночасно публічний `/api/server` повернув HTTP 200 JSON:

```json
{"status":"online","address":"51.75.44.14:2219","players":0,"maxPlayers":500,"name":"United Ukraine | Сервер: 1","source":"game-query","updatedAt":"2026-10-20T22:18:56.995Z"}
```

Це вимірювання на зазначений момент UTC (вже 21 жовтня за Europe/Bucharest), не постійні налаштування. 0 тут підтверджений відповіддю ігрового сервера, не заглушка. Число 1000 зі старого PRIME не використано.

## Підготовлене локальне виправлення

- `/online.json` переписується на існуючий `/api/server?format=online` **до SPA fallback**. Нова Vercel function не потрібна: залишається 12 JS-функцій.
- `lib/online.js` повертає сумісний JSON; `api/server.js` використовує для нього той самий `getStatus`, що для JSON сайту і Discord XML.
- Джерела моніторингу не змінено: спочатку SA-MP UDP info query до `51.75.44.14:2219`, далі наявний `MONITOR_API_URL` або запис саме цієї адреси в `https://api.open.mp/servers`.
- Перевіряються status, адреса, відомий source, цілі числові лічильники, `0 <= players <= maxPlayers <= 10000`, місткість більша за нуль. Сторонні адреси, рядки замість чисел і некоректні дані не публікуються.
- `public/Project/info.json`, IP/порт, CDN, ресурси та APK не змінені. Server ID `1` збігається в обох наявних релізних гілках конфігурації.
- Додано маршрут у локальний API-сервер і проксі Vite для перевірки `/online.json` під час розробки.

Приклад здорового моніторингу, що відповідає наведеному вимірюванню:

```json
{"crmp_new":{"1":{"players":0,"maxPlayers":500}}}
```

Це об'єкт, не масив; верхній ключ `crmp_new`, вкладений рядковий ID `1`, поля `players` і `maxPlayers` — JSON numbers. Ім'я, IP і порт клієнт отримує як раніше з `/Project/info.json`.

## Недоступність моніторингу

Якщо всі джерела не відповідають або дані не пройшли перевірку, HTTP 200 повертає:

```json
{"crmp_new":{}}
```

Заголовки `X-Server-Status: unavailable`, `X-Online-Source: unavailable`, `Cache-Control: no-store`. Немає вигаданих 0/1000, null-лічильників, HTML чи внутрішнього тексту помилки. Це свідома політика: без підтверджених чисел сервер не оголошується доступним. Його відсутність у меню під час збою моніторингу не означає підтверджену зупинку самої гри. Поведінку UI фізичного телефону для порожнього об'єкта ще потрібно перевірити в клієнтському чаті.

Для здорового моніторингу заголовки `X-Server-Status: online`, `X-Online-Source: game-query|configured-monitor|open.mp`. У reader є 15-секундний memory cache і об'єднання одночасних запитів; здоровий HTTP-відгук допускає 15 секунд edge cache. З урахуванням цих двох рівнів дані можуть відставати приблизно на 30 секунд. Новий endpoint не роздає останні відомі числа безстроково після збою.

GET і HEAD — HTTP 200, `application/json; charset=utf-8`, `nosniff`, коректна довжина тіла. HEAD без тіла. OPTIONS — 204 без моніторингу. CORS `*`, GET/HEAD/OPTIONS, Accept/Content-Type/X-Unity-Version; без cookie чи редиректів. Записи POST/PUT/PATCH/DELETE — JSON 405.

## Перевірка та межі публікації

Локально пройшли:

```text
npm run test:online   # 8 сценаріїв, включно зі справжнім loopback HTTP
npm run test:discord  # 8 сценаріїв збереження XML/моніторингу
npm run test:site     # 4 сценарії існуючої логіки сайту/моніторингу
npm run build        # TypeScript і Vite
```

Перевірено точний і переписаний маршрути, ключі й типи, source/адресу, легітимний нуль, збій/некоректні лічильники, CORS/methods/HEAD, спільний кеш, пріоритет перед fallback та незмінність формату старих API. Ці тести не доводять, що новий rewrite вже застосовано на Vercel.

**Статус цього виправлення: перевірено локально; власник погодив commit і push.** Фактичний результат відправлення перевіряється за Git, а готовність нового маршруту — окремим публічним HTTP-запитом після деплою. Попередній коміт `d2ab886` має успішний Vercel deployment status на GitHub, але `/online.json` в ньому ще не реалізований. Нових змін БД для online API немає; штатний deploy:build проєкту, як і раніше, запускає загальний migration runner.

Після публікації перевірити саме основний домен:

```text
curl -i https://united-rp.com.ua/online.json
curl -I https://united-rp.com.ua/online.json
curl -i https://united-rp.com.ua/api/server
```

Очікуються не HTML, а application/json, `crmp_new`, ID 1 при здоровом моніторингу, числа з актуального джерела та `X-Online-Source`. При порівнянні двох запитів врахувати кеш і те, що онлайн може змінитися між вимірюваннями. Виробничі джерела навмисно не вимикалися для симуляції збою — outage перевірений локальними тестами. Після перевірки домену повторити меню «Виберіть сервер» і logcat на фізичному телефоні; у цьому проєкті результат телефона не підтверджений.
